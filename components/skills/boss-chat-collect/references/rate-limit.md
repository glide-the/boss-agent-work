# 限流与异常处理手册

## 已观察到的限流表现（2026-07）

连续打开约 500-600 个会话后：

1. 聊天列表只返回前 50 条，滚轮滚动不再加载新项（刷新页面也一样）。
2. 无滑块、无报错提示，属于静默限流。

## 处理策略

1. 列表完整时：用 `collect-scroll.js` 扫场采集（~2s/条）。
2. 列表只剩 50 条后：切换 `collect-search.js`，对剩余队列逐条搜索定位（~4s/条）。
   - 搜索命中率非 100%：`searchMiss: true` 的记录先跳过，换姓名重试或标记「待确认」。
3. 全程每条落盘 JSONL；内核重置后从文件恢复 doneKeys 续跑，绝不重采。
4. 检测到滑块/安全验证文本 → 停止，报告用户，不要尝试绕过。

## 其他异常

- 「查看职位」未打开详情页：标记 `job detail tab not found`，该岗位 JD 记为缺失，消息数据保留。
- 聊天无职位入口（job 为 null）：标记 noJobEntry，仍记录消息流。
- 点击超时（列表项 5s 未响应）：记录 error 并跳过，不中断批次。

## 节奏建议

- 单条间隔 ≥1.5s；每 40-50 条暂停一次并同步落盘到工作区。
- 不要并发开多个详情页标签；不要点击「发简历/换电话/换微信/发送」。
