# 求职消息自动生成

核心原则：消息**不是静态模板**，而是根据当前任务（如「四、当前任务」中的目标分类）+ 候选人简历，在运行时按方向生成。内置 `messages.js` 模板只作兜底。

## 消息结构（硬规则）

- 4-5 句短句，逐句单独发送（每句一条 Enter），不发长段落。
- **第一句必须与该岗位需求直接相关**：引用岗位标题中的方向词（如「大模型应用」「情感陪伴」「算法」），说明为什么匹配。
- 第 2-4 句从简历提取卖点，按岗位方向排序：最贴合该方向的经历/项目在前。
- 末句：技术栈或到岗时间 + 期待沟通。
- 语气自然、像真人打招呼；不堆砌、不夸大、不写简历上没有的内容。

## 生成步骤

1. **读简历**：默认 `/Users/dmeck/project/boss-agent/zhangmaofeng/` 下的简历（PDF，可用 pdf 技能提取文本）。提炼 5-8 个可复用卖点，例如：方向关键词、代表项目、开源贡献、技术栈、到岗时间。
2. **按任务方向映射卖点**：每个目标分类选一个 `kind`（任意字符串，作为队列项的 kind），确定该方向的卖点优先级。映射思路：
   - 偏工程/应用方向 → 项目工程经验、技术栈在前；
   - 偏产品方向 → 需求拆解、PRD、评测体系、技术+产品复合背景在前；
   - 垂直场景方向（如情感陪伴、某行业）→ 该场景的直接项目经验放第一句之后，其余通用卖点殿后；
   - 支持/运维方向 → 环境搭建、排障、文档沟通能力在前。
3. **生成并注册**：为每个 kind 写一个生成函数并 `setMsgsForKind` 注册；`makeQueue(cards, doneKeys, kind)` 把 kind 绑进队列，`runChunk` 内部经 `pickMsgs` 自动取用。

## 注册示例

```js
// 任务：AI情感陪伴(杭州)、AI解决方案(杭州)
JG.setMsgsForKind("emotion", (t) => [
  `您好，我对贵司「${t}」很感兴趣，情感陪伴/虚拟人方向我有一线实战经验。`,
  "我独立设计过情感化宠物 Agent，覆盖角色生成、AI Profile、长短期记忆与主动消息触发链路。",
  "我设计过 text/action/emotion 结构化输出协议，并搭建过 Golden Case 多轮对话评测集。",
  "技术上熟悉 RAG、MCP、tool calling，是 Langchain-Chatchat 开源项目核心贡献者。",
  "技术栈 TypeScript/Python，一个月内可到岗，期待进一步沟通。",
]);
JG.setMsgsForKind("solution", (t) => [
  `您好，「${t}」要求的 AI 方案设计与落地能力正是我的主攻方向。`,
  "我有 LLM 应用工程与 Agent 工作流实战经验，能把模糊需求拆成可落地的技术方案。",
  "熟悉 RAG、MCP 与主流大模型能力边界，参与过智谱 AI 生态 SDK 与 RAG 工程化。",
  "技术栈 TypeScript/Python、FastAPI、Docker，一个月内可到岗，期待进一步沟通。",
]);
```

## 注意事项

- 简历换人或更新后重新提炼卖点，不要沿用旧卖点。
- 同一任务内不同 kind 的消息要有明显差异（第一句与卖点排序），避免被平台判为批量复制。
- `clearCustomMsgs()` 可清空已注册的方向，新任务开始前先清空再注册。
